## Port is more than changing three constants

- Change H/I/topk to2048/512/8, keep MAXT8. Derived HB/IB=128/32, HQ/IQ=32/8; FC1 tiles32, FC2 tiles16. E is runtime256.
- **Structural loop bounds:** FC1 `wv[10][2]`, `sv[10]` and both loops `<10` at136–140/164 must become H/256=8. FC2 equivalents `[5]`/`<5` at258–262/310 become I/128=4. Retaining old bounds would read beyond rows even after top-level constants change. Assert H%256=0,I%128=0,H%128=0,MAXT*topk<=128.
- FC1 dynamic shared maximum becomes20480bytes plus static storage; check compiler-reported registers/spills before tuning. Scratch partial output becomes4MiB atMAXT8; activation workspace and partial traffic must be counted in fullcalls.
- qf expects ordinary packed FP4 weight rows and128×4 swizzled scales (`sf_quad_offset:90`). Current b12x may use its own weight permutation. First construct qf inputs from raw checkpoint, not blindly from b12x prepared buffers; prove dequantized rows/scales match, with all nibble positions. CPU bijection check proves offsets cover storage, **not** that the installed layout is identical.
- qf W13 is **up then gate** (23,203–210); raw current reference is **gate then up**. Either explicit one-time row permutation of weights+scales+global factors or load-index adjustment is mandatory. Record conversion bytes/time separately from steady inference.
- qf quant16 uses quantizing global multiplier `gs`, RN E4M3 and approximate reciprocals (46–68); alpha is used with0.25 to reverse x2 integerization. Map `a1/a2` from actual FI effective preprocessor outputs, not raw checkpoint globals or Humming reciprocal names. qf g1/g2 alpha is perexpert; its a1/a2 pointers are scalar. Current selected effective activations are global-amax replicated, so assert uniformity before taking scalar. Do not generalize to arbitrary perexpert calibrated scales.
- qf rounds FC1 up/gate toBF16, SwiGLU toBF16, then requantizes (203–226). Compare exact quant payload and preactivation stages against CUTLASS and selected scalar/direct; this boundary differs from Humming's FP32 FC2 input and must stay explicit.
- The public wrapper's process-static `part_out,done` (393–397) is **not a safe multi-stream vLLM workspace contract**. Port must accept explicit per-instance workspace and outputs, initialize counters before graph capture, and never share writable counters across overlapping forwards. No runtime allocations in timed calls.
- Repeated expert within the same token is unsupported: its token mask and `s_w[token]` lose multiple slot weights. Real topk yields unique IDs, assert in fixtures. Cross-token repeats are intended. All-invalid padded routes have no final owner and may leave output stale: explicitly zero valid masked outputs or forbid this fixture until implemented, never silently pass graph padding. Counter rearming must be tested on alternating routes/token counts.

## Smallest controlled implementation sequence (pending root review)

1. Prepare a standalone extension with the geometry/layout/workspace fixes above. Do not patch installed FI. Add a compile-time duplicate-reuse switch retaining identical arithmetic: reuse-on owner first expert slot handles token mask; reuse-off each route handles its own token. Reduction must consume corresponding slots correctly in both variants. PDLoff initially. This separates arithmetic and expert reuse effects instead of treating the whole external kernel as a unit.
2. CPU raw checkpoint conversion and decoded-scale/weight equality; synthetic unique/disjoint/shared route fixtures and zero-padding contract. GPU only after grant: L19M1 first for quant/GEMM staged parity against actual CUTLASS/direct plus FP32; no speed promotion from tolerance alone.
3. M1/2/4/8 with disjoint real capture slices, report uniqueexpert distribution. Compare reuseoff/on, current automatically selected path and forced direct/split alternatives; include setup/quant/reduction in fullcall. Sequential graph replays and two independent workspaces, changed inputs, repeated numerical distribution. Weight traffic estimate = actual distinct experts×(3HI packedFP4+scales), label estimate not measured bandwidth; use profiler counters before asserting DRAM savings.
4. Only if reuse helps, separate PDLoff/on and measured cold/multi-layer sequence. Then scoped vLLM opt-in registration/compile key and c1/c4 serving. No agentic until final combined stack.

## Stage1 implemented, CUDA validation pending

`prepare_port.py` checks upstream SHA and every replacement count, emits `qf_moe_port.cu`. Reuse is a uniform kernel argument controlling first-owner selection, token mask and final slot-owner mapping; DP4A math remains identical between variants. PDL is fixedoff. All scratch/output tensors are passed explicitly. Each invocation enqueues output/counter memsets on its current stream, including graph capture: fully padded rows/batches therefore remain zero and no stale completion count is inherited. These operations belong in timed fullcalls. Caller must retain a separate workspace for overlapping streams/graphs; same-stream sequential reuse is intended. Input routes must be unique within each token; invalid IDs are padding. Duplicate-within-token inputs are outside the API contract.

`prepare.py` converts raw gate/up to up/gate, swizzles E4M3 scales, and maps globals to current FI effective reciprocal-amax contract. `check_checkpoint_cpu.py` validated all256 L19 experts against installed reorder, swizzle and scale helper bodies; removed exactly one forced `.cuda()` from swizzle only in the CPU oracle. It also reconstructed every scale byte using qf's address formula. Result `checkpoint_cpu.json`: weights/scales exact, effective scales exact, CUDA uninitialized. This does not establish activation quant parity, CUDA arithmetic or races.

Two source-structure tests failed before source generation and pass afterward. Build script targets sm120a with CUDA_VISIBLE_DEVICES empty and records source/artifact identity, never calls the extension API. GPU stage must include M3: actual installed `_DIRECT_MICRO_CUTOVER_PAIRS=32`, strict routed_rows<32 means top8 auto-direct is eligible for M1/2/3, not M4/8. Instrument actual backend choice and include forceddirect wherever supported. No automatic GPU launch.
