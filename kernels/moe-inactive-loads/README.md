# Inactive-warp operand register loads

CPU prototype only; no GPU compilation, numerical result, activation proof or timing yet. This is distinct from changing tile size or task order.

The installed M128 kernel already predicates inactive M16 MMA fragments. This variant additionally predicates shared-to-register operand copies in entirely inactive MMA warps using `valid_rows > (warp_idx & 3) * 16`. All 32 lanes share the condition. Any warp with an active first or second M16 fragment executes the original copies. Full M128 tasks always satisfy the guard; their FC1/FC2 methods remain byte-for-byte unchanged. The common FC2 A/SFA call has a new always-true condition for full tiles.

`prepare.py` copies the actual baseline SHA `993783308233288ddfa77293e9dbabdc825ba5bfdcc4dcc41e842a895ec33445` and produces a distinctly named complete class. It changes 24 FC1-tail copy sites, 6 FC2-tail copy sites and the FC2 A/SFA call site. Every view creation, accumulator initialization, wait/release, pipeline advance, fence, named barrier, quantization/store and task publication statement remains unchanged. Constructor M128 guard and a new K2048/I512 constexpr guard constrain applicability. The registration helper additionally accepts only NVFP4/SiLU at this geometry.

`plugin.install()` defaults to `off`; explicit `on` swaps only the factory class. Both modes append their effective full-source SHA to the existing dynamic cache key while preserving all existing fields. Static/micro keys are untouched. A nonempty dynamic in-memory cache, previously replaced class, unexpected source, forced backend or unsupported geometry fails closed. No serving registration or installed source is modified.

CPU evidence in `results/cpu_review_1` includes CUDA-hidden real imports/host constructors, off/on cache identity and dirty-cache rejection. `test_source.py` removes precisely the allowed additions and requires exact remaining AST equality, and rejects a barrier mutation. It also checks that the predicate equals “at least one active M16 fragment” for every valid row count and MMA warp. These checks do not instantiate GPU device code.

Review gates before a later micro: compile both exact source variants, inspect emitted SASS/PTX for intended load suppression and retained synchronization, record actual registers/spills/shared memory, then bind actual launched graph nodes to candidate artifacts. The unchanged declared register budget232 is not evidence of unchanged compiled register use. Measure complete scalar expert calls on identical operands and changed-input/routes graph replay, with source-qualified caches and reversed measurement order. If there is a real timing win, require before-atomic contribution diagnostics and numerical self-noise controls before any serving proposal. No speed or quality equivalence claim follows from CPU tests.

## Prepared first screen

`run.sh UNIQUE_TAG off|on` holds the shared GPU lock and runs exactly one explicitly selected mode in a fresh child process. It snapshots 14 owned input files, verifies captured operands plus 13 installed/helper files, records the exact PID/group lifetime, and cleans only that child/group. The existing development container is retained. Do not run until a GPU slot is granted.

`micrograph.py` uses current scalar `prepare_exact` and full `apply` on L19/M1024 and M4096, always M128/K2048/I512. Each mode uses independent compiler caches with source-qualified native keys. Tests cover original, modified input/routes/route weights, synthetic sparse-tail routes and restored input; save paired outputs and input hashes. M1024 synthetic routes give32-row tails; M4096 includes64-row tails and full128 fragments. Graph/fresh errors are gated at exploratory relL2<=.02; CUTLASS differences remain diagnostics. Every mode must show its actual class name in GPU kernel events from graph replay or it fails. The profiler runs after timing (three30-sample blocks); timings are CUDA graph spans, never summed kernel durations.

After GPU process completion `artifacts.py` records every native artifact hash and runs `cuobjdump --dump-resource-usage/--dump-sass` if available. Missing tool or spill data remains explicitly unresolved. `compare.py OFF_DIR ON_DIR` requires successful source-matched controls, identical prompt operand hashes, complete scenario lists and paired output error gates. A positive single pair would still need reversed startup order, actual emitted-code review, numerical self-noise and before-atomic contribution diagnostics. No automatic chain, serving run or agentic evaluation is included.
