## New, falsifiable experiments (our proposals)

1. **Expert-deduplicated DP4A micro path versus current direct-micro.** Port only H2048/I512/top8 for captured L19 M1/2/4/8. Explicitly reconcile checkpoint gate/up ordering, tiled weight-scale layout, calibrated effective globals, BF16 intermediate casts and RN quantization. First verify FC1/FC2 quant bytes and dequant-reference errors; then graph fullcalls over multiple disjoint captures, reporting unique expert counts and shared-expert frequency. Compare current scalar-selected backend and forced direct/micro/static, not a weak generic CUTLASS baseline. Reject if gains disappear with actual route overlap or layout preparation. This is different arithmetic/work reuse from our prefill task ordering and Humming tensorcore path.

2. **Fixed-order finalization without another launch.** Isolate the public kernel's partial-output plus last-CTA counter protocol from its DP4A math. Prototype on our native task-order diagnostic: keep canonical contribution payloads unchanged, then sum slot order with one final BF16 cast. Smallest test is L19/M4096 recorded contributions and changed-routing graph replay; demand exact fixed reference and stress counter rearming, padded/zero-work tiles. Compare extra scratch/traffic against current atomics. This targets measured accumulation-order drift and may make task ordering more usable; no speedup assumed. Check overlap with upstream issue5375 before implementation; novelty here is single-launch last-CTA finalization, not merely deterministic reduction.

3. **Routed/shared output merge fusion only.** Borrow fastkernels' joint accumulation boundary, preserving distinct NVFP4 calibration and current auxiliary-stream work. Fuse shared sigmoid gating/add into a final routed reduction when dependencies permit; do not serialize shared GEMM into routed work. Smallest test captures the current output tensors and gate at L19 M1024/M4096, compares separate epilogue against fused merge including event waits and live stream overlap. Reject if the extra dependency outweighs saved launch/read/write. This differs from the previously proposed dual-input quantizer: it merges outputs and does not alter activation scales. Requires callgraph trace before code, since compiler may already fuse the relevant add.

Priority: finish queued RN layer validation and native serving tests first; these are scoped next experiments, not grounds to abandon existing evidence. First idea helps decode; third is most directly relevant to prefill. None changes learned routing or imports external throughput claims into our progress chart.
